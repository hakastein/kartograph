# Сборщик объявляет себя ключом приложения в объявлении cliche

Здесь решено, где сборщик записывает, что он потребляет, что производит и какая у него область действия.

## Контекст

Чтобы построить план и после правки перезапустить только нужные сборщики, kartograph должен знать входы, выходы и
область действия каждого сборщика до его запуска. Сборщики — скрипты на JavaScript, которые kartograph исполняет
через [cliche](https://github.com/hakastein/cliche): cliche находит скрипты, читает их объявление
`exports.definition` чистым литералом без выполнения модуля и запускает их программно (`Run` с собранным `Input`,
возвращённое значение), а `Env` позволяет не давать скрипту `fs` и `fetch`.

Объявление cliche принимает только свои ключи (`short`, `long`, `args`, `flags`); незарегистрированный ключ делает
его нечитаемым. cliche v0.2.0 даёт механизм расширения: приложение регистрирует ключи верхнего уровня в
`Config.Keys` (`Key{Required bool; Read func(Literal) (any, error)}`). cliche читает значение такого ключа тем же
разбором литерала, отдаёт его `Read` с местом (`Literal{Line, Column, Value}`) каждого значения, вложенные
включительно, и кладёт результат в `Command.Keys`. Отказ `Read` — нечитаемое объявление, `*ScriptError` с местом
литерала, которому отказали через `Literal.Errorf`.

## Решение

- **kartograph регистрирует в `Config.Keys` cliche свой ключ сборщика** (например, `collector`). Его значение —
  литерал с входами (виды фактов, glob файлов, внешние данные), выходами и областью действия `file` или `snapshot`.
- **Объявление читается без выполнения скрипта.** Содержимое ключа и его проверку задаёт kartograph в `Read`; отказ
  называет место в скрипте.
- **Незарегистрированный ключ в объявлении — нечитаемое объявление**, как любой неизвестный ключ cliche.
- **Скрипт, который конфиг проекта называет сборщиком, обязан иметь ключ сборщика.** Без него объявление
  нечитаемо, снимок не публикуется. Библиотечные модули, которые сборщики подключают, объявления не имеют и иметь не
  обязаны.
- **План — DAG по объявленным входам и выходам.** Цикл — ошибка объявления (`index_failed`, причина `plan_cycle`,
  [ADR-0003](0003-an-error-is-a-yaml-document-with-a-closed-code.md)).
- **Сборщик запускается из Go программно** со структурированным входом и возвращает значение; через argv и печать
  сборщик с ядром не общается. Живые `fs` и `fetch` ему не выдаются: внешние входы объявляются и попадают в снимок
  как данные. Это контракт воспроизводимости, а не песочница: cliche скриптам доверяет.
- Механизм реализован в cliche v0.2.0; kartograph подключает cliche этой версией или выше через `go.mod`.

## Не решено

- Имя ключа и его схема: входы, выходы и внешние данные —
  [DEV-14014](https://yt.macrodigital.ru/issue/DEV-14014).

## Отвергнуто

- **Отдельный литерал kartograph рядом с `exports.definition`** (например, `exports.collector`). Его пришлось бы
  читать без выполнения модуля собственным разбором литерала: второй разборщик того же подмножества JavaScript, свои
  места ошибок и два объявления одного скрипта, которые могут разойтись.
- **Объявление в отдельном файле рядом со скриптом.** Два файла на сборщик, которые меняются вместе и проверяются
  порознь; объявление и код расходятся при переименовании.
- **Объявление, которое возвращает выполненный скрипт.** План нельзя построить без запуска каждого сборщика, а
  вычисленное объявление нельзя проверить по месту в литерале.

## Следствия

- Сборщик — скрипт команды cliche, поэтому его объявление проходит проверку cliche v0.2.0: `short` — строка в одну
  строку от 1 до 60 символов, `long` — строка; без любого из них объявление нечитаемо.
- Ключ кеша сборщика `file` строится из его объявленных входов: путь, содержимое файла, подключённые им модули,
  конфиг, версии API и парсеров, объявленные входные факты.
